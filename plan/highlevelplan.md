# PROJECT ROADMAP: Bit-Plane XNOR-Popcount SOD
**Objective:** Prove that decomposing 8-bit images into binary bit-planes and using C-optimized XNOR logic outperforms YOLO-tiny in speed and memory on CPU-bound drone hardware.

---

## 1. DATA INFRASTRUCTURE (The "Eyes")
*Goal: Prepare VisDrone data to preserve detail while enabling bitwise speed.*

*   **Input Standard:** Standardize all images to **640 x 640**. (This matches YOLOv8-tiny’s default, ensuring a "Fair Fight").
*   **Bit-Plane Decomposition:**
    *   Convert RGB to `uint8` Grayscale.
    *   Slice the `uint8` into **8 separate binary matrices** (Bit 0 to Bit 7).
*   **Memory Alignment (The "Secret Sauce"):**
    *   Use NumPy to pack bits into `uint64_t` integers. 
    *   **The Math:** A 640-pixel row becomes exactly **10** unsigned 64-bit integers ($10 \times 64 = 640$).
    *   **Storage:** Your input tensor for C is now `[8 bit-planes, 640 rows, 10 integers]`. This is 32x smaller than FP32.

---

## 2. THE CHALLENGER ENGINE (The C-Backend)
*Goal: Build the XNOR-Popcount kernel that bypasses floating-point units.*

*   **Layer 1: The "Bit-Serial" Conv:**
    *   This layer takes the 8 bit-planes.
    *   **The Operation:** XNOR the 1-bit weights against each bit-plane.
    *   **The Recomposition:** Perform `Popcount`, then bit-shift the result by the plane’s significance ($Result += Popcount \ll i$).
    *   **The Hardware Hook:** Use C-intrinsics like `__builtin_popcountll` (x86/GCC) or `_mm_popcnt_u64` (Intel AVX).
*   **Hidden Layers: The "Binary-Binary" Conv:**
    *   Standard NAS-BNN layers.
    *   Pack 64 channels into one `uint64_t`.
    *   **Performance:** One `XNOR` + `POPCNT` instruction now calculates **64 multiplications and additions** in a single clock cycle.
*   **The Bias/BN Fusion:**
    *   Store biases as `int16`. 
    *   After the bit-serial sum, add the bias. 
    *   **Thresholding:** If the result $> 0$, the next layer gets a `1`, else `0`.
